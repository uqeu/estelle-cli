## §0 — Standing rules (non-negotiable)

These are the founder's rules. They are not style preferences; each one was paid for.

1. **GREEN IS A CLAIM ABOUT WHAT WAS MEASURED, NEVER ABOUT WHAT WAS NOT.** Before you trust a passing
   test, say which half it covers, and prove the test can fail. A test that cannot go red is a
   violation, not a pass.
2. **NON-EMPTY IS NOT CORRECTLY-PARSED.** "The list has items" proves something was read, never that
   the right thing was. Pair every vacuity guard with a shape assertion on the parsed value.
3. **Asserting a mutation APPLIED is necessary and NOT sufficient — assert the resulting STATE.** A
   `str.replace` is silent on a miss, and the language can absorb an applied edit without producing
   the state the mutant is named for. Set `PYTHONDONTWRITEBYTECODE=1` for any Python-side harness.
4. **Name the LINE the failure came through, or say you do not know which line it was.** Never
   attribute a symptom to a plausible cause you did not trace.
5. **Wire it or do not land it.** A module that compiles, tests green, and is called by nothing is not
   done. If you cannot reach the call site, the module waits.
6. **Honesty mandate.** No fabricated numbers, benchmarks, capabilities, or model names. If it was not
   measured, do not state it as fact. A confident hallucination about Estelle's own design is exactly
   the failure Estelle exists to prevent.

**Secrets — absolute:**
- Never read, enumerate, copy, or materialise credentials from `.env`, `stress_accounts.json`,
  `estelle_accounts.json`, or `estelle_experience.json` — under any goal.
- Never print a secret value. Report `file:line + type` only.
- Never run `railway variables --kv` against this service.
- `web/` is a separate worktree. Do not touch it from CLI work.

### D1 — 🔴 PRIVACY: internal retrieval context is rendered as Estelle's answer

> **✅ LANDED 2026-08-07** — see `docs/2026-08-07-D1-answer-pipeline.md`. One `/deep-search`
> round-trip; working memory rides the question field for non-conversational turns and is skipped
> for conversational ones; `AnswerReply.text` carries the answer only. The description below is the
> historical record of the defect.

**Symptom:** asking a question returns a transcript turn beginning `Working memory (local snapshot
scoped to this request: …)` followed by local file paths and the raw Repo-graph text. The customer sees
retrieval plumbing where the answer should be.

**Root cause — exact:** `tui/src/main.rs:2463-2478`. `AnswerReply.text` is the customer-visible
transcript string, and it is built with `format!` from the Working-memory header, the local file path
list, `local_text`, and `team_text`. This is deliberate concatenation, not a leak through an edge case.

```rust
// tui/src/main.rs:2464 — the defect, verbatim
text: format!(
    "Working memory (local snapshot scoped to this request: {})\nSent to Estelle's configured model path; not added to the team's Repo graph.\n{}\n\nRepo graph (the team's swept copy; shown separately because it may differ)\n{}",
    ...
),
```

**The distinction that matters:** retrieval context is **model input**, never **assistant output**.
`working_memory_prompt()` at `main.rs:2481-2508` is correct — that string goes to the model. The
`AnswerReply.text` at 2463 is what the human reads, and it must contain the answer only.

**Fix shape:** `AnswerReply` must carry the answer text and the provenance **as separate typed
fields**. `working_paths` already exists on the struct (`main.rs:2477`) and is already populated — the
UI can disclose "3 local files were sent" from that field without splicing prose into the transcript.
Choose one answer to render (or render both under explicit labels in a *disclosure* surface, not the
answer body).

**Acceptance test (must go red first):** construct an `AnswerReply` from a fake response pair where
`local_text` and `team_text` are distinguishable sentinels, render the transcript, and assert the
rendered turn contains **neither** the literal `"Working memory ("` **nor** any path from
`working_paths`. Note `main.rs:6560` currently asserts `rendered.contains("Repo graph")` — that
existing test encodes the defect and must be inverted, not deleted silently.

> **✅ LANDED 2026-08-07** — the scene's lifecycle owner is now `has_submitted_question`

**Acceptance test:** render with a non-empty composer and zero submitted turns; assert the welcome copy

### D3 — 🟠 Dark theme paints a grey sheet instead of inheriting the terminal

**Symptom:** the pane renders as a grey rectangle that does not match the user's terminal, because
ANSI "black" is rendered as grey by most terminal themes.

**Root cause — exact:** `tui/src/main.rs:131-141`:

```rust
fn background(self) -> Color {
    Self::Dark => Color::Black,      // line 133
    Self::CreamInk => Color::Black,  // line 141
```

`Color::Black` is ANSI 0, a *painted* colour. `Color::Reset` inherits the terminal's own background.
The value is then used to fill whole panes at `main.rs:3535`, `4597-4598`, `4635`, and passed to
`composer.render_ref_with_background` at `4977-4980`.

**Fix shape:** dark theme inherits (`Color::Reset`). Verify the cream/ink theme separately — cream is a
deliberate painted surface per the founder's visual taste, so **do not blanket-replace all four sites.**
Decide per theme and say which you changed.

**Acceptance test:** assert the rendered buffer's background style for the main pane is `Color::Reset`
under the dark theme. This is the mutant-prone one — assert the *resulting style*, not that an edit
applied.
